## What it does
TaskScan reads a UTF-8 text file
and prints one row per token: type, lexeme, line and column (both start at 1).
It only tokenizes. It does not run the tasks or check statement grammar.

## Files
```
src/taskscan/TaskScan.jflex   the JFlex specification (hand-written)
src/taskscan/Main.java        console driver
src/taskscan/Token.java       token record
src/taskscan/TokenType.java   token kinds
generated/taskscan/TaskScanner.java   GENERATED by JFlex, do not edit
lib/jflex-full-1.9.1.jar      JFlex
build.sh, run_tests.sh        build and test scripts
tests/inputs                  16 test inputs (written before running)
```

## Generate, compile, run
```
./build.sh                                   # generate with JFlex, then compile into out/
java -cp out taskscan.Main tests/inputs/file.txt
./run_tests.sh                               # run all tests, writes tests/results.md
```
The same steps by hand (also works on Windows with `;` replaced by your shell's separator):
```
java -jar lib/jflex-full-1.9.1.jar -d generated/taskscan src/taskscan/TaskScan.jflex
javac -encoding UTF-8 -d out generated/taskscan/TaskScanner.java src/taskscan/*.java
java -cp out taskscan.Main <input-file>
```
The program exits with status 0 when there are no lexical errors, 1 when there are, and 2 for usage or file errors.

## Language summary
- Keywords (lowercase): `add done remove list show where`
- Identifiers: letter or `_`, then letters, digits or `_`
- Integers: digits only (no sign, no decimals)
- Strings: `"..."` on one line; a backslash makes the next character part of the string; escapes are not decoded
- Operators: `= == != < <= > >=`; punctuation `; ,`
- Skipped: spaces, tabs, form feeds, line ends (LF, CRLF, CR), `#` comments to end of line
- Errors: any other character, or a string with no closing quote. The scanner reports the position and keeps going.
- Columns count characters, so a tab counts as 1. A leading UTF-8 BOM is not special-cased.

## Known limitations
- No decimals, negative numbers, dates or escape decoding (`2.5` becomes INTEGER, error, INTEGER).
- A string ending in a lone backslash at the end of a line is reported as an unterminated string followed by an unexpected `\`.
- Characters outside the Basic Multilingual Plane (such as emoji) in strings were not tested.
- Parsing, executing tasks and a GUI are out of scope.
